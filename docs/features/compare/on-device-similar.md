# 아이디어: 유사 의류 검색을 폰 안에서 하기 (온디바이스 임베딩)

> **아직 정한 기능이 아니다.** 2026-11-17 moneyhipo가 해 볼 만하다고 적어 둔 아이디어다. 하기로 정하면 이 문서를 기능 문서 형식([_template.md](../_template.md))으로 바꾸고 완료 조건을 채운다. 결정 전까지는 [progress.md](../../progress.md) `미결정 사항`에 둔다.

## 지금 방식
[similar-search.md](similar-search.md): 서버가 CLIP으로 사진을 임베딩하고 FAISS·코사인 유사도로 옷장에서 TOP 3를 찾는다. 그래서 **서버가 없으면 유사 검색을 못 한다** (2026-11-17 기준 Vultr 서버가 아직 없음).

## 아이디어
임베딩 모델을 앱 안에 넣어 폰에서 바로 계산한다.

1. 옷 사진 → 폰 안 모델 → 벡터
2. 옷장 옷의 벡터는 등록할 때 계산해 Room에 저장
3. 쇼핑 중인 상품 사진의 벡터를 옷장 벡터와 코사인 유사도로 비교 → 단계(`매우 비슷` / `비슷`)로 표시. 옷장이 수백 벌 정도면 FAISS 없이 전부 비교해도 충분하다

## 좋은 점
- 서버 없이 유사 검색이 된다 (게스트·오프라인에서도)
- 옷장 사진이 서버로 가지 않는다 (개인정보 부담 감소)
- 서버 CLIP 메모리(약 500MB)가 빠져 서버 요금제를 낮출 수 있다

## 걸리는 점
- **모델 크기·속도**: 서버 CLIP(ViT-B/32 기준 수백 MB)을 그대로 넣기는 무겁다. MobileCLIP 같은 작은 모델이나 양자화를 따져 봐야 한다. AAB 크기 제한과 저사양 폰 속도를 잰다
- **변환**: PyTorch → ONNX(ONNX Runtime Android) 또는 TFLite(LiteRT). 변환 뒤 서버 결과와 벡터가 거의 같은지 확인
- **정확도**: 작은 모델은 지금 평가(FashionCLIP + v2 문장 88.0%, 실제 옷장 29장 82.8%)보다 떨어질 수 있다. 같은 평가 도구(`sandbox/moneyhipo/eval/`)로 비교한다
- **추가 학습 데이터**: DeepFashion은 **평가에만 쓴다** (CLAUDE.md 데이터셋, 11-07 결정). 추가 학습(파인튜닝)을 하려면 상업 사용이 되는 데이터나 직접 찍은 사진만 쓴다
- 자동 분류(종류·색)와 AI 점원 등 Claude API를 쓰는 기능은 그대로 서버가 필요하다. 이 아이디어는 **유사 검색만** 옮긴다

## 처음 해 볼 것 (하기로 하면)
1. 후보 작은 모델 2~3개를 PC에서 기존 평가 도구로 돌려 정확도 비교
2. 가장 나은 것을 ONNX/TFLite로 변환해 크기·서버와의 벡터 차이 확인
3. sandbox 앱에서 사진 한 장 임베딩 시간 측정 (실제 폰)
4. 결과를 progress.md에 적고 팀원과 할지 정한다
