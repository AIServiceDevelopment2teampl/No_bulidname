# 기능: 미리 입어보기 (AI 가상 피팅)

> **도전 목표** (2026-11-04 결정). MVP 기능(00-overview.md 기능 목록 1~15)을 마친 뒤 시간이 남으면 출시 전에 넣는다. 안 되면 빼고 출시한다.

## 설명
고른 옷을 마네킹에 입힌 모습을 AI 가상 피팅 서비스로 만들어 보여 준다. "이 옷을 사면 내 옷이랑 어울릴까"를 사기 전에 눈으로 보는 용도다.

- **여는 곳 두 군데**
  1. AI 점원 패널의 `이 상품이랑 입혀보기`: 지금 보는 상품 + '어울리는 내 옷'에서 고른 옷
  2. 내 옷장에서 여러 벌 고르기 → `마네킹에 입혀보기`: 내 옷끼리
- 한 번에 아우터·상의·하의에서 한 벌씩, 최대 3벌
- **마네킹**: 앱에 넣어 둔 기본 마네킹만 쓴다. 체형은 슬림 / 보통 / 넉넉 (초안). 사용자 본인 사진은 받지 않는다 (초안, 개인정보 부담)
- 결과에는 `AI가 만든 참고 이미지` 표시와 "실제 핏·색과 다를 수 있어요" 안내를 붙인다
- **저장 위치**: 결과 이미지와 코디(입힌 옷 목록)는 **폰에만** 저장한다(Room + 앱 저장소). 서버는 외부 서비스로 중계만 하고 옷 이미지·결과 이미지를 저장하지 않는다(디스크, DB, 로그 모두)
- **외부 서비스**: 서버에 GPU가 없어서(Vultr CPU 4GB) 외부 가상 피팅 API를 쓴다. 어느 서비스로 할지는 미결정 ([progress.md](../../progress.md) 미결정 사항). API 키는 서버에만 둔다
- **비용**: 장당 약 $0.06~0.08 (2026-11-04 웹 검색, 비교 사이트·재판매처 기준이라 공식 가격 확인 필요). 서비스에 따라 옷 한 벌마다 따로 호출해야 해서 3벌이면 비용·시간이 최대 3배가 될 수 있다. 그래서 하루 사용 횟수를 제한한다 (횟수 미결정, 시안은 5회)

## 입력
- 옷 최대 3벌: 쇼핑 중인 상품은 상품 id(상품 이미지), 내 옷은 옷 id. 각 옷의 종류(아우터/상의/하의)
- 마네킹 체형

## 출력
- 결과 이미지 1장 (앱이 받아서 폰에 저장)
- 오늘 남은 횟수

## 예외 상황
- 사진 없는 옷(영수증 등록 등): 고를 수 없게 흐리게 보여 준다
- 같은 종류를 두 벌 고름: 나중에 고른 것으로 바꾼다
- 신발·가방·액세서리: 고를 수 없다 (지원 종류만)
- 하루 횟수를 다 씀: 외부 서비스를 부르지 않고 "오늘은 다 썼어요, 내일 다시 해 주세요"
- 외부 서비스 실패·시간 초과: 횟수를 차감하지 않고 다시 시도 안내
- 옷 사진 배경이 복잡하거나 사람이 입은 사진: 결과가 나쁠 수 있다고 안내한다
- 다른 사용자의 옷 id: 거절한다
