# 기능: Google Play 출시

## 설명
앱을 Google Play에 정식(프로덕션) 출시한다. 프로젝트 목표의 하나이고, 일정이 가장 긴 작업이라 개발과 나란히 진행한다.

**확인된 조건 (2026-10-21 기준, 출시 전에 Play Console에서 다시 확인):**
- 2023-11-13 이후 만든 **개인 개발자 계정**은 프로덕션 출시 전에 **테스터 12명 이상이 14일 연속 참여한 비공개 테스트**를 거쳐야 한다. 그 전에는 프로덕션 메뉴가 잠겨 있다.
- 2026-08-31부터 새 앱은 **Android 16 (API 36) 이상을 타깃**으로 해야 한다.
- 남의 웹사이트를 허락 없이 WebView로 보여 주는 것이 주목적인 앱은 스팸 정책 위반이다 ([architecture.md](../../architecture.md) 주요 위험 참고).

**일정:**
| 시점 | 할 일 |
|------|-------|
| 8주차 (지금) | Play Console 개인 개발자 계정 만들기·본인 확인, 테스터 12명 이상 모으기 시작 |
| 10주차 | 개인정보처리방침 페이지 게시, 데이터 보안 양식 초안 |
| 11주차 | 첫 빌드를 비공개 테스트 트랙에 올리고 테스터 참여 시작 (14일 시작) |
| 12~13주차 | 테스트 중에도 새 빌드를 올려 기능을 채운다. 테스터 의견 기록 |
| 13~14주차 | 14일이 차면 프로덕션 액세스 신청 |
| 15주차 | 프로덕션 출시 |

## 입력
- 서명된 AAB, 스토어 등록정보(이름, 설명, 스크린샷, 아이콘), 개인정보처리방침 URL, 데이터 보안 양식 응답, 테스터 목록

## 출력
- Play 스토어에 공개된 앱

## 예외 상황
- 테스터가 14일 안에 빠짐: 12명 밑으로 떨어지지 않게 여유 있게 모은다 (15명 이상 권장)
- 프로덕션 액세스 신청 거절: 거절 사유대로 고치고 테스트를 더 한 뒤 다시 신청
- WebView 정책으로 심사 거절: 인앱 브라우저를 빼거나 줄인 빌드로 공유하기·스크린샷 경로만 출시하고, 이유를 발표에서 설명한다
- 서버가 꺼져 있으면 심사 중 앱이 동작하지 않음: 심사 기간에는 서버를 계속 켜 둔다
